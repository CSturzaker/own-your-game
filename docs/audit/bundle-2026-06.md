## Findings & fixes

### 1. Zod was shipping to every page (~18 KB gz) — fixed

`react-dom` (~42 KB gz) is the expected floor. The surprise was an 18.8 KB
chunk on **every** page containing Zod (`ZodError`, `invalid_type`, 322
`_zod` refs). Zod is build/pipeline-time validation only — it has no place
in the browser.

**Cause:** client code imported the `THEMES` _value_ from `~/lib/voice` →
`schemas/voice.ts`, which builds `z.object(...)` schemas at module scope.
Rollup can't tree-shake those side-effectful calls, so importing `THEMES`
dragged Zod in. The path onto every page: `PlayerCardOverlay`
(`BaseLayout`, all pages) → `~/lib/player-context` → `~/lib/squad-filters`
→ `THEMES`.

**Fix:** extracted `THEMES`/`Theme` into a Zod-free `schemas/themes.ts`
(re-exported by `schemas/voice.ts` and `~/lib/voice` so public APIs are
unchanged), and repointed the client-reached libs (`squad-filters`,
`squad-url`) at `~/lib/themes`. Zod is now absent from the client bundle
(verified: no `ZodError` in `dist/_astro/*.js`).

### 2. The player-card modal loaded eagerly on every page (~8 KB gz) — fixed

`PlayerCardOverlay` (mounted `client:idle` in `BaseLayout` on every page)
**statically** imported `PlayerCardModal` → the whole Radix Dialog +
StreamPlayer + PlayerChips + player-card graph shipped everywhere, even on
pages with no tiles, and even on **mobile** — where the overlay never
opens (it only intercepts at ≥lg; mobile navigates to `/voice`).

**Fix:** `React.lazy(() => import("./PlayerCardModal"))` + `Suspense`. The
chunk now loads on the first tile click (desktop only); mobile never
fetches it. The overlay's click-interception logic stays eager.

## Verified clean (no action needed)

- **Single React runtime** — one `react-dom` chunk; no duplicate React across pages.
- **No dictionaries client-side** — Epic 10's strings-as-props pattern holds; no `*/dictionaries/*.json` in client JS.
- **Only used Radix primitives** ship — Dialog (modal), Popover (language switcher + squad filters), Tooltip (signature row). No unused primitives.
- **Hydration directives** are appropriate — below-the-fold/non-critical islands are `client:idle`/`client:visible`, not `client:load` (the one `client:load` is a demo-only fixture).

## Floor

`react-dom` (~42 KB gz) sets the per-page floor. Replacing React with
Preact is explicitly out of scope (significant rewrite). The remaining
~35 KB on a typical page is the Astro client runtime + the page's own
islands + shared Radix primitives — all in use.
