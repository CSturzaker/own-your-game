## Findings

### 1. Heading order — footer column headings skipped levels (FIXED)

`Footer.astro` rendered its three column headings ("The Letter", "The
Squad", "Project") as `<h5>`, so every page's heading sequence jumped
`h1`/`h2` → `h5` (WCAG 1.3.1 Info & Relationships / 2.4.10). CI's axe pass
missed it because `heading-order` is a best-practice-tagged rule, not
`wcag2a/aa` — exactly the gap this audit targets.

**Fix:** footer headings → `<h2>` (visual unchanged — the classes drive
the styling). Sequence is now gap-free on every page (`h1 → h2 …`).
Verified across all five pages.

### 2. Forced-colors mode (best practice — follow-up)

Under `forced-colors: active` (Windows High Contrast), axe reports
`color-contrast` on `/` and `/squad`. axe's contrast check is unreliable
in forced-colors (the OS overrides the palette), so this is most likely
noise — but it isn't a substitute for a real Windows High Contrast pass
(verifying focus rings, buttons, tags, and the player scrim stay
distinguishable). Forced-colors support isn't strictly WCAG 2.1 AA, so
this is best-practice. Follow-up filed.

### 3. GUI screen-reader spot-checks (manual — follow-up)

The **semantic** layer was audited in code and is sound (below). The
literal VoiceOver + NVDA/JAWS spot-checks the AC asks for need a human on
macOS/Windows with the screen reader running — they can't be done
headlessly. Follow-up filed for Craig to complete before launch.

## Area-by-area results

### Keyboard navigation — pass

- **Skip link** — visible only on focus, moves focus to `<main>` (`layout.spec.ts`).
- **Focus rings** — 3px functional-cyan `focus-visible` outline on interactive elements (`#007FB8` on paper = 3.92:1, clears the 3:1 non-text threshold).
- **Player-card modal focus trap** — open focuses close; Tab/Shift+Tab cycle within; Escape closes + restores focus (`dialog-focus-trap.spec.ts`).
- **Language switcher** — Tab/Enter/arrows/Escape (`footer.spec.ts`, `i18n.spec.ts`).
- **Squad filters** — chips open popovers; arrow nav; Escape closes (`squad.spec.ts`).
- **Letter waypoints** — keyboard-reachable; `scrollIntoView` honours reduced-motion (`LetterRail.tsx`).

### Screen-reader semantics — pass (GUI spot-check deferred)

- **Modal** — Radix Dialog: `role="dialog"`, `aria-modal`, labelled by the card title; axe-clean open.
- **Filter results** — `aria-live="polite"` count in `SquadFilters` announces "Showing N voices" on change.
- **Voice counter** — region `aria-label`; decorative digits `aria-hidden`.
- **About stat count-up** — animated digits `aria-hidden`; visually-hidden real value announced once (`CountUp.tsx`).
- **Tiles** — first-name `dir="auto"`; the link's accessible name carries name + country + position.

Verified clean against the two documented divergences (CLAUDE.md): no

(white fails at every size) is never used for content — the brand-fill
role uses `#074661`/`#007AB1`, both AA-clear. `fn-cyan`/`fn-orange` are
not used as text anywhere (focus-ring/border only).

### Reduced motion — pass

`prefers-reduced-motion: reduce` honoured: the global guard zeroes
animation/transition durations (home rotation pauses to the static pill;
counter dot stops pulsing; About count-up is instant). Both `LetterRail`
(`scrollIntoView` becomes instant) and the player-card swipe (no
rubberband+slide) branch explicitly on `prefersReducedMotion()`.

### Language & direction — pass

`<html lang>` correct in all five locales; `<html dir="rtl">` on Arabic,
`ltr` elsewhere; user-content names carry `dir="auto"`.

### Reflow & headings — pass

No horizontal scroll at 320px CSS width on any page (WCAG 1.4.10). Exactly
one `<h1>` per page; heading sequence gap-free after the footer fix.

### Forms — n/a (pass)

No forms except the squad filter dropdowns (Radix Popover/Select, labelled);
their result count announces via `aria-live`.

### axe regression — pass

0 violations (`wcag2a/2aa/21a/21aa`) across all pages in en + ar — CI gate intact.
